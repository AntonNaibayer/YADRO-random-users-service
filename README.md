# YADRO Random Users Service
fullstack-приложение для загрузки случайных людей из внешнего API, сохранения данных в базе данных и просмотра информации через web-интерфейс.

---

## Описание проекта

Приложение позволяет:

- автоматически загрузить 1000 случайных людей при старте backend-сервера;
- сохранить полученные данные в PostgreSQL;
- просматривать список людей через web-интерфейс;
- загружать дополнительное количество людей через форму на главной странице;
- открывать страницу конкретного человека;
- получать случайного человека по адресу `/random`;
- работать с большим количеством записей через пагинацию;
- запускать проект локально или через Docker Compose;
- запускать backend-тесты;

Это основной рекомендуемый способ запуска.

Перед запуском должны быть установлены:

- Docker

Из корня проекта:


После запуска будут доступны:


## Локальный запуск без Docker

### 1. PostgreSQL

Нужно иметь запущенный PostgreSQL.

Пример переменных окружения для локального запуска backend:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=yadro
DB_USER=postgres
DB_PASSWORD=postgres

BASE_URL=https://api.randomdatatools.ru
```

Создайте файл:

```text
backend/.env
```

и добавьте туда эти переменные, изменив значения при необходимости.

---

### 2. Backend

Перейти в папку backend:

```bash
cd backend
```

Установить зависимости:

```bash
uv sync
```

Применить миграции:

```bash
uv run alembic upgrade head
```

Запустить backend:

```bash
uv run uvicorn src.main:app --reload
```

Backend будет доступен по адресу:

```text
http://localhost:8000
```

Swagger:

```text
http://localhost:8000/docs
```

---

### 3. Frontend

Перейти в папку frontend:

```bash
cd frontend
```

Установить зависимости:

```bash
npm install
```

Создать файл:

```text

```


Frontend будет доступен по адресу, который покажет Vite. Обычно это:

## Обоснование выбора технологий


Для backend я выбрал **FastAPI**, потому что уже немного работал с ним и он хорошо подходит для таких небольших сервисов. В нём есть автоматическая документация через Swagger, а также хорошая поддержка асинхронного кода.

Для работы с базой данных я использовал **SQLAlchemy 2**. SQLAlchemy хорошо работает вместе с Alembic, который я использовал для миграций.

В качестве базы данных выбрал **PostgreSQL**, потому что это одна из самых популярных реляционных баз данных, которая часто используется в backend-разработке. Для этого задания она хорошо подходит, так как нужно хранить данные о людях, делать выборки, пагинацию и работать с JSON-полем для сохранения полного ответа от внешнего API.

Для frontend я выбрал **React + TypeScript**. React позволяет быстро сделать интерфейс с таблицей, формой загрузки и отдельными страницами. TypeScript помогает заранее описать структуру данных, которые приходят с backend, и уменьшает количество ошибок при работе с ними.

Для стилей я использовал **Tailwind CSS**, так как с ним можно быстро собрать аккуратный интерфейс без большого количества отдельных CSS-файлов.

Для управления Python-зависимостями я использовал **uv**. Он быстрее устанавливает зависимости, создаёт lock-файл и позволяет удобно запускать команды проекта через `uv run`.

## Основная функциональность

### При старте backend

При запуске backend:

1. создаётся HTTP-клиент для внешнего API;
2. проверяется количество людей в базе данных;
3. если база пустая, приложение загружает 1000 случайных людей из внешнего API;
4. полученные данные сохраняются в PostgreSQL;
5. если в базе уже есть данные, повторная начальная загрузка не выполняется.

это сделано, чтобы при какждом перезапуске сервера заново не загружалась информация о 1000 пользователей

---

## Хранение данных

В базе данных используется таблица `people`.

Основные поля вынесены в отдельные колонки:

- `id`
- `gender`
- `first_name`
- `last_name`
- `phone`
- `email`
- `address`
- `raw_data`

Поле `raw_data` хранит полный исходный JSON-объект, полученный от внешнего API. (по заданию не понятно нужны ли остальные данные о человеке или нет, поэтому был реализован такой вариант)

## API endpoints

После запуска backend API доступен по адресу:

```text
http://localhost:8000
```

Swagger UI:

```text
http://localhost:8000/docs
```

### Получить список людей

```http
GET /people?limit=20&offset=0
```

Возвращает список людей с пагинацией.

Пример ответа:

```json
{
  "items": [
    {
      "id": 1,
      "gender": "Мужчина",
      "first_name": "Иван",
      "last_name": "Иванов",
      "phone": "+7 (999) 123-45-67",
      "email": "ivan@example.com",
      "address": "Россия, г. Москва...",
      "raw_data": {}
    }
  ],
  "total": 1000,
  "limit": 20,
  "offset": 0
}
```

Параметры:

| Параметр | Описание |
|---|---|
| `limit` | Количество записей на странице |
| `offset` | Смещение от начала списка |

---

### Загрузить новых людей из внешнего API

```http
POST /people/load?count=100
```

Загружает указанное количество людей из внешнего API и сохраняет их в БД.

Пример ответа:

```json
{
  "loaded": 100
}
```

Параметры:

| Параметр | Описание |
|---|---|
| `count` | Количество людей для загрузки |

---

### Получить конкретного человека

```http
GET /people/{person_id}
```

Пример:

```http
GET /people/1
```

Если человек найден, возвращается информация о нём.  
Если человека с таким ID нет, возвращается `404`.

---

### Получить случайного человека

```http
GET /random
```

Возвращает случайного человека из базы данных.

При обновлении страницы или повторном запросе сервер выбирает новую случайную запись.

## Тесты

Backend покрыт тестами с использованием:

- pytest
- pytest-asyncio
- httpx
- SQLite in-memory для тестовой базы
- mock/fake client вместо реального внешнего API

В тестах внешний API не вызывается.

Запуск тестов:

```bash
cd backend
uv run pytest
```

Запуск тестов с покрытием:

```bash
uv run pytest --cov=src --cov-report=term-missing
```

Покрываются основные сценарии:

- создание `Person` из данных внешнего API;
- получение списка людей;
- пагинация;
- получение человека по ID;
- `404`, если человек не найден;
- загрузка людей через `/people/load` с замоканным внешним API;
- получение случайного человека через `/random`;
- обработка пустой базы для `/random`.

## Особенности реализации

### Начальная загрузка 1000 людей

По условию задания при старте сервера нужно загрузить 1000 случайных людей.

В приложении это реализовано в `lifespan` FastAPI:

- при старте создаётся HTTP-клиент;
- проверяется, есть ли записи в БД;
- если таблица пустая, загружаются 1000 людей;
- если записи уже есть, повторная загрузка не выполняется;
- при остановке приложения HTTP-клиент корректно закрывается.

Такой подход предотвращает дублирование данных при каждом перезапуске сервера.

---

### Внешний API

Для работы с внешним API используется отдельный HTTP-клиент.

Код клиента находится в:

```text
backend/src/clients/
```

Общий базовый клиент вынесен отдельно, чтобы при расширении проекта можно было легко добавить другие HTTP-клиенты.

---

### Пагинация

Так как количество людей может быть большим, список не отдаётся полностью.

Endpoint `/people` поддерживает параметры:

```text
limit
offset
```

Frontend отображает по 20 пользователей на странице и показывает номера страниц.

---

### Случайный человек

Endpoint:

```http
GET /random
```

выбирает случайную запись из базы данных.  
Если база пустая, возвращается `404`.
